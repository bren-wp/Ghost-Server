# Ghost Server 0.12.0

Ghost Server 0.12.0 adds local Fleet health history and attention detection without introducing external telemetry.

## Added

- Local Fleet health timeline for successful and failed server probes.
- CPU, memory and disk utilization snapshots stored with each successful probe.
- Local Attention state when CPU, RAM or disk utilization reaches 90% or higher.
- Selected-server Fleet history panel with the latest 100 records.
- Bounded fleet-history persistence using the same atomic JSON + backup recovery model as other Ghost Server local state.
- Clear selected-server Fleet history action with explicit confirmation.
- History is preserved across application restarts.

## Privacy and security

- Fleet history is local-only under the Ghost Server app-data directory.
- No passwords, passphrases, SSH secrets or database credentials are stored in Fleet history.
- No Fleet health data is uploaded or sent to third-party services.
- Bulk Fleet probes remain limited to already trusted private-key profiles that can authenticate without a passphrase.
- Selected-server probes continue to clear the session secret immediately after use.

## Delivery

Ghost Server 0.12.0 remains gated by version metadata, release-note validation, source hygiene, XAML event-wiring validation, .NET analyzers with warnings as errors, Windows self-contained publish, installer verification, Portable launch smoke and Setup install/launch/uninstall smoke tests.
