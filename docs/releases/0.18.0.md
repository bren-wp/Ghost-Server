# Ghost Server 0.18.0

Ghost Server 0.18.0 focuses on dead-code removal, maintainability enforcement and regression prevention after the responsive-window and operation-safety releases.

## Dead code audit

The production UI and service layer were audited conservatively so WPF members that are referenced through XAML are not misclassified as unused C#.

Confirmed dead code removed:
- obsolete `IsOperationCancellation` helper left behind after the generation-aware remote-operation cancellation model;
- unused `SidebarBorder` XAML name, which generated an unnecessary backing field;
- unused `HeaderAddServerButton` XAML name, which generated another unnecessary backing field.

The audit also confirmed:
- no currently unused keyed XAML theme resources in the audited resource dictionaries;
- no declaration-only private underscore fields in the audited production source;
- no declaration-only service methods in the manually inspected SSH, terminal, profile, settings, Fleet history and JSON storage services.

## Permanent CI dead-code gate

A new `scripts/dead-code-audit.ps1` gate now scans the complete `src/GhostServer` tree on every pull request and main build.

It fails CI when it finds:
- a private C# method that is not called by C# and is not wired from XAML;
- a private underscore field referenced only by its own declaration;
- a public/internal method under `Services` that has no source reference outside its declaration;
- an `x:Name` that generates a field but is not referenced by code or another XAML construct;
- a keyed XAML resource that is declared but never consumed.

The gate is intentionally conservative. It does not delete code automatically; it blocks the build and surfaces candidates for review.

## UI/UX polish from production screenshots

- Replaced the remaining Windows-default scrollbar chrome with a Ghost-specific scrollbar template.
- Removed white scrollbar channels and arrow-button surfaces.
- Vertical and horizontal scrollbars now use a dark track, compact rounded thumb and Ghost-blue drag state.
- Track paging remains functional in both orientations.
- Sidebar navigation now uses one strict geometry for every visible item: a 32 px icon column, a 24 px centered glyph and a fixed 10 px label gap.
- All 11 visible sidebar destinations use the same icon and label styles.
- Removed six obsolete hidden navigation buttons left behind after workspace grouping.
- Removed the write-only `_activeNavButton` field.
- Service/Docker log navigation now marks the real System parent workspace instead of depending on a hidden Logs navigation control.

## XAML wiring hardening

The existing XAML event-wiring audit now includes responsive-window events:
- `SizeChanged`
- `StateChanged`

This closes the gap introduced when 0.17.0 added responsive window lifecycle handlers.

## Quality contract

0.18.0 keeps the existing requirements:
- source hygiene with no TODO/FIXME/NotImplemented markers;
- analyzers and warnings as errors;
- exact version/release-note consistency;
- release provenance verification;
- self-contained Windows x64 publish;
- Portable launch smoke test;
- Setup install, launch and uninstall smoke test;
- exact validated artifact upload for release publication.
