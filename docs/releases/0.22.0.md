# Ghost Server 0.22.0

Ghost Server 0.22.0 extends the 0.21.0 operation-safety work with durable local-state rollback, race-safe profile and Fleet interactions, safer terminal locking and improved narrow-window behavior.

## Coordinated local mutations

- Profile save/delete and SSH trust changes now use a dedicated single-flight profile mutation gate.
- Fleet probes, Fleet-history clearing and alert acknowledgement use a dedicated Fleet-history mutation gate.
- Profile import, profile mutation, Fleet-history mutation and remote administrative mutation gates are mutually coordinated in both directions.
- Administrative mutation buttons and profile-context controls reflect the combined exclusive-operation state instead of allowing conflicting actions to start.
- Existing Lock session behavior remains intentionally available as an emergency/security action.

## Durable profile persistence

- Save server disables Save/Cancel while persistence is active and rolls the live collection back if servers.json cannot be written.
- Delete profile disables confirmation actions while persistence is active and restores the deleted profile at its previous position on failure.
- SSH host-key approval no longer clears the pending fingerprint before durable persistence succeeds.
- Failed host-key approval restores the previous fingerprint and keeps the user informed instead of reporting a false success.
- Reset SSH trust captures the target profile, disconnects only the matching terminal context and restores the previous fingerprint if persistence fails.
- Fleet inventory refreshes after successful or rolled-back profile changes so trust/profile state remains coherent across workspaces.

## Connection metadata correctness

- LastConnectedUtc persistence is isolated from the successful SSH connection result.
- If only local connection-history persistence fails, the connection remains Connected and the status reports the metadata warning.
- The previous LastConnectedUtc value is restored in memory when that write fails.

## Fleet-history reliability

- History retention trimming is built as a snapshot and is committed to the live list only after FleetHistoryStore persistence succeeds.
- Bulk and selected Fleet probes restore the previous in-memory history when the durable write fails.
- Clear Fleet history restores the previous history on failure.
- Alert acknowledgement restores the previous acknowledgement timestamp on failure.
- Concurrent Fleet-history mutations are rejected instead of racing the shared local history file.

## Session lock safety

- Repeated Ctrl+L / Lock session actions are single-flight.
- Lock cancels an in-flight terminal connection first.
- If a terminal transition is still completing, Lock waits for that transition to settle before explicitly disconnecting the shell.
- The session secret and auto-refresh state are cleared immediately as part of the security action.

## Transactional window reset

- Reset window size shares the Settings save busy state.
- The reset temporarily disables its action and Save settings.
- If settings persistence fails, the previous stored dimensions, live geometry, fit-window state and pending resize-persistence state are restored.
- A failed reset no longer leaves the visible window in a state that contradicts settings.json.

## Responsive summary cards

- Fleet, Alerts and Trends summary grids switch from four columns to two below the tight responsive breakpoint.
- Summary cards use shared Ghost styling.
- Long summary labels wrap into a reserved two-line label area instead of clipping at the 640×440 minimum window size.
- Dense GridView tables remain horizontally scrollable while ordinary page chrome continues to prefer wrapping.
