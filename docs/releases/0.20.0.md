# Ghost Server 0.20.0

Ghost Server 0.20.0 focuses on local-state reliability and interaction polish while preserving the bounded, non-fullscreen window behavior introduced in earlier releases.

## Safe window-size persistence

- Ghost Server can remember the user's last normal-window size.
- The preference is enabled by default and can be disabled from Settings.
- Only normal-window dimensions are persisted.
- The temporary Fit window state is never stored as the next startup size.
- Saved dimensions are normalized and clamped to safe application limits.
- On startup they are clamped again against the current Windows work area before use.
- The restored window remains centered and never restores into a true Maximized/full-screen state.
- Resize persistence is debounced to avoid writing settings on every resize pixel.
- A pending resize is flushed before the window closes so the final normal size is not lost.
- Startup resize events cannot save anything until the existing settings file has been fully loaded and applied.
- Settings includes a Reset window size action that returns to the safe default dimensions.

## Settings completion

- Added a Remember normal window size setting.
- Added Reset window size.
- The optional backup location now has both Choose folder and Clear actions.
- Clearing the backup path is persisted as no default directory after Save settings.

## Local storage reliability

Settings, server profiles and Fleet history now serialize load/save access through a process-lifetime, per-store `SemaphoreSlim`.

This prevents overlapping operations from racing on the same atomic `.tmp` / `.bak` files while preserving the existing crash-safe write strategy. The gates intentionally live for the process lifetime so a late async completion during window shutdown cannot observe a disposed synchronization primitive.

Covered stores:
- `settings.json`
- `servers.json`
- `fleet-history.json`

External profile import/export remains independent because it targets user-selected external files.

## Settings interaction state

- Settings now tracks unsaved changes explicitly.
- Save settings is disabled when the displayed values match the persisted model.
- Changing the refresh interval, Remember normal window size, or backup folder enables Save settings and shows an Unsaved changes status.
- Leaving and returning to Settings preserves pending values until they are saved or explicitly reloaded.
- Reset window size remains an isolated immediate action and does not silently persist unrelated pending Settings changes.
- XAML initialization changes are ignored by the dirty-state tracker so startup cannot produce a false unsaved state.

## CI efficiency

- Windows CI now uses a pull-request concurrency group with cancel-in-progress enabled.
- New commits on the same PR cancel stale grouped runs so only the newest synchronized head consumes validation time.
- Main-branch CI uses the same latest-run principle for rapid successive pushes.

## Compatibility

The settings format remains backward-compatible. Existing settings files that do not contain the new window fields use the safe defaults automatically.

No password or private-key passphrase persistence was introduced.
