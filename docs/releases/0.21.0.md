# Ghost Server 0.21.0

Ghost Server 0.21.0 strengthens remote-operation safety, profile integrity and interaction feedback.

## Administrative operation state

- Remote administrative mutations now drive one shared busy state.
- Service start/stop/restart, Docker start/stop/restart, firewall changes, Safe Update, configuration restore, configuration backup, scheduled-task creation/deletion and process termination are mutually exclusive.
- While one mutation is active, all mutation buttons are disabled using the existing Ghost disabled style.
- The server list plus Edit, Reset trust and Delete profile are also temporarily disabled so a server-context change cannot accidentally cancel a running administrative operation.
- Lock session remains intentionally available as an explicit security/emergency action.
- A persistent Admin action badge appears in the status bar while the mutation lock is held.
- Disabled Ghost buttons use the normal arrow cursor instead of retaining a misleading hand cursor.
- Mutation acquire/release is centralized so backend lock state and UI busy state cannot drift apart.

## Safe close during remote mutations

- Closing the application while a remote administrative mutation is active now requires an explicit Ghost-styled confirmation.
- The warning explains that closing stops local waiting/operation context but cannot guarantee rollback of a command already started on the server.
- Remote cancellation is deferred until the complete close flow is approved.
- If unsaved Settings also exist, cancelling at the later Save/Discard/Cancel step leaves the remote operation untouched.
- The existing Settings and window-geometry close flows remain intact.

## Confirmation continuation safety

- Ghost confirmation tasks now use `TaskCreationOptions.RunContinuationsAsynchronously`.
- Async callers no longer resume inline inside the confirmation button click stack.
- This reduces reentrancy risk for remote mutation and window-closing continuations.

## Profile-context protection

- Reset SSH trust now captures the target profile before awaiting terminal disconnect.
- Connection UI is updated only when that same profile remains selected.
- If `servers.json` persistence fails, the previous pinned fingerprint is restored instead of leaving in-memory trust state inconsistent with disk.

## Transactional profile import

- Profile import now has its own busy guard, preventing parallel import workflows.
- Import is disabled while a remote administrative mutation is running.
- Imported profiles are merged into a separate candidate list first.
- The candidate list is validated and written to `servers.json` before the UI collection is modified.
- If persistence fails, the live profile collection remains unchanged.
- If an imported profile replaces the selected or terminal server context, remote operations and the terminal are safely cancelled/disconnected before the UI switches to the new profile.
- Fleet inventory is refreshed after a successful import.

## Portable profile security

- External profile exports/imports do not carry pinned SSH host-key trust.
- External profile exports/imports do not carry `LastConnectedUtc` connection history.
- Every imported server therefore requires local SSH host-key approval before connection.
- Passwords and private-key passphrases remain session-only and are never included.
- Duplicate `host:port + username` SSH identities are rejected centrally by ProfileStore, including manually edited external JSON.
